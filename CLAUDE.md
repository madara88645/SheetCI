# SheetCI — guidance for Claude

SheetCI is a local-first CLI that scans `.xlsx` workbooks for risky formula patterns and
produces Markdown/HTML/JSON audit reports. It is a metadata scanner, not a calculation
engine: it never evaluates formulas, never uploads files, and never calls an LLM.

## Commands

```bash
uv run pytest                                    # full suite
uv run sheetci scan examples/clean-model.xlsx    # expected: PASS, exit 0
uv run sheetci scan examples/broken-commission-model.xlsx --out report.md --html report.html
```

The broken example is *supposed* to exit `1`. `report.md` and `report.html` are gitignored;
never commit them.

## Layout

- `sheetci/scanner.py` — `WorkbookScanner`, the detectors, risk scoring. The only module
  that touches openpyxl.
- `sheetci/reporters.py` — Markdown, HTML (inline Jinja template), and JSON output.
- `sheetci/cli.py` — typer CLI. Exit code is `1` on FAIL, `2` on scan/IO error, `0` on PASS.
- `examples/` — fixture workbooks, generated by `scripts/create_example_wb.py`. Regenerate
  with `uv run python scripts/create_example_wb.py` rather than editing the binaries.
- `docs/superpowers/specs/` and `docs/superpowers/plans/` — design docs for in-flight work.
  Read the relevant spec before changing detector behaviour.

## Detector invariants

Any change to detection must preserve these. They are the regression surface:

- `examples/broken-commission-model.xlsx` scans to **FAIL** with `BROKEN_REF`,
  `SELF_REFERENCE`, and `CACHED_ERROR` present.
- `examples/clean-model.xlsx` scans to **PASS**.

Reducing noise is welcome; reducing detection power while claiming to reduce noise is not.
If a fix makes a real finding disappear, it is the wrong fix.

Risk scoring lives in one place. Severity weights are `critical` 30, `warning` 10, `info` 3,
capped at 100; a workbook fails if any critical exists or the score reaches 70. Changing a
rule's severity changes pass/fail behaviour for every user — treat it as a design decision,
not a tweak.

## Conventions

- Python `>=3.11`. Dependencies are managed with `uv`; do not add runtime dependencies
  without being asked.
- All repository text in English: code, comments, docstrings, commit messages, branch names,
  PR titles and bodies, issue text, review comments.
- Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`), with a scope where it
  helps (`fix(scanner): ...`).
- Prefer small, scoped, reversible pull requests. No unrelated refactoring in a PR that is
  about something else.
- New behaviour arrives test-first. Never relax an existing assertion to make a suite go
  green — if a test fails unexpectedly, report the actual output and explain it.

## Hard rules

- Never commit or push directly to `main`. Work on a branch.
- Never merge a pull request without the repository owner's explicit approval.
- Never force-push a shared branch.
- Do not touch `.github/workflows/`, `pyproject.toml` dependency pins, or `uv.lock` unless
  the task is specifically about them.
- Any subagents spawned while working on this repository run on the cheap tier
  (`model: 'sonnet'`) — including synthesis, review, and critic roles. An unset model is a
  violation, not a default.
